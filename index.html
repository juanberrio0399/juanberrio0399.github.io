01 — Profile

Engineer who ships, not just reports

I'm a Cloud & Data Engineer with 6+ years building and automating the platforms that run data in production. I don't just process the data — I build the serverless infrastructure that produces, stores and serves it, with Infrastructure as Code and CI/CD.

My current project incrementally ingests an international logistics operator's Excel files, consolidates them into a DuckDB warehouse, and publishes a serverless dashboard (Cloudflare + React + DuckDB-WASM) that refreshes from a one-click run on the office PC plus a cloud ingestion that runs daily and whenever a file arrives — with no server to maintain and ~$0 infrastructure.

I design with an architecture mindset: separating compute, storage and presentation, choosing serverless, and optimizing for cost. Currently advancing on AWS and Systems Engineering, on the path to Cloud Solutions Architect.

DataForge Cloud

Production

The cloud side of an international logistics operator's customs data: an operations dashboard (with SLA compliance per client) and a settlement validator, both reading Parquet from R2 and running the SQL in the browser.

How I automate it
  • Two ways in. When someone saves a watched Excel in SharePoint, Power Automate posts it to a Cloudflare Worker, which triggers the ingestion in GitHub Actions. The heavy files (settlements, tax forms) are processed on an office PC and pushed to R2.
  • The cloud ingestion runs once a day and every time a file arrives, with a 2-hour brake so it doesn't burn Actions minutes.
  • Both dashboards sit behind Cloudflare Access. A Pages Function reads R2 through a binding and DuckDB-WASM runs the queries client-side, so there's no query server.
  • A Worker checks the age of every table every 2 hours, and a daily GitHub Actions job flags any dataset older than 30 h.

Impact: leadership reads the numbers without opening a single Excel, no server to maintain, ~$0 infrastructure.

DataForge

Production

The ETL engine behind the platform. It turns thousands of business Excel files into a clean, queryable warehouse, and it runs with one double click.

How I automate it
  • Before it runs, it checks the PC: Python, packages, OneDrive folders, permissions, credentials and the R2 connection. It installs what's missing and stops on anything it can't fix.
  • A catalog stores each file's modification date, so only new or changed files get read, deduplicated by their key into one Parquet per source.
  • If more files landed while it was running, it runs again on its own (up to 30 rounds, with a guard that stops it when a round makes no progress).
  • Every run is logged with user, PC, start, end and result, and it says loudly at the end if the cloud step didn't finish.

Impact: 36M+ records from 13K+ Excel files · package-level reconciliation across 5 sources · 30 h freshness alerts.

Customs Operations Automation

Production · RPA

The repetitive work around a customs operation, turned into 15 double-click tools that a non-technical team runs on its own: portal downloads, validations, cross-checks and document packages.

How I automate it
  • Playwright with a persistent browser profile: you log in to the customs portal once and every tool reuses that session. A lock allows one browser per PC, and the tools run at low priority so the PC stays usable.
  • It downloads the manifests and settlements a control sheet marks as pending, and only marks them done after checking the file actually landed in the right folder.
  • It fills the settlement validation sheet from the downloaded files (date, rate, exchange rate, tax total) and notes every shipment that doesn't add up. Other tools cross-check shipment by shipment: incidents per master, taxes paid against deposits.
  • Anything that deletes simulates first, asks you to type YES and keeps a backup copy. A separate Playwright bot uploads supporting documents to an e-commerce client's portal, matching each file to its master by digits.
  • 6 Power Automate flows: two turn arrival pre-alert emails into SharePoint records, four push Excel files from SharePoint to a Worker that feeds the cloud pipeline. For colleagues' PCs there are portable converters with embedded Python, so there's nothing to install.
PythonPlaywrightopenpyxlPower AutomateCloudflare Workers

Impact: portal work that was done master by master is now a list in Excel and a double click; each tool runs one pass and says what it did.

Video Forge

Public repo

A YouTube Shorts factory that runs in the cloud with no PC involved: it writes, narrates, edits, checks licenses, uploads and schedules, then measures how each video did and decides what to make next.

How I automate it
  • 84 GitHub Actions workflows do the compute: the script comes from a chain of free LLMs (Gemini first, five fallbacks), the voice from Kokoro, and FFmpeg assembles licensed clips, sound and captions.
  • A hard license gate: if a clip isn't from an allowlisted source, nothing gets published and I get an alert.
  • State and memory live in a Cloudflare Worker and R2. Every 2 hours a planning job checks past decisions against their own success criterion and builds the next schedule from the hours that perform best.
  • One Telegram bot with a Mini App is the control panel. My other systems plug into it through service bindings, and a weekly job (Radar) opens improvement issues on my repos.

Impact: a publishing team's routine running on free infrastructure at $0 a month, with 53 test suites on every PR.

Signal Halo Studio

Private · v1.0

A Windows app that pulls the best moments out of a long video and edits them for vertical (Shorts, Reels, TikTok) or horizontal, with captions, music and a watermark.

How it works
  • It proposes cuts from the video's most-replayed curve and the transcript, and I approve or adjust each one before anything gets edited.
  • Vertical mode follows whoever is talking with two ONNX models (face detection and active speaker) and splits the screen when two people talk.
  • Captions use word-level timing. If Claude is on the PC it fixes names and misheard words and suggests titles; without it, everything still works on plain rules.
  • Approved finals go up to Cloudflare R2 and I manage them from the Telegram bot; videos marked as used are deleted after 24 h. Nothing to install: portable Python and ffmpeg pinned by version and SHA-256, no admin rights.

Serverless RAG Assistant

Live · AI

An AI assistant that answers questions grounded in your own documents, 100% serverless on Cloudflare. Deployed and live.

How I automate it
  • RAG: documents → chunks → embeddings → Vectorize (vector DB); on a question it retrieves the closest chunks and an LLM answers.
  • Runs on Cloudflare Workers AI with a cross-encoder reranker, an optional reasoning mode (DeepSeek-R1), conversation memory in D1 and durable ingestion of long documents with Workflows. No server to maintain, ~$0 infrastructure.
  • Treats every document as hostile input: instructions hidden in a page get stripped before they reach the index, and it says "I don't know" when the answer isn't in the docs.
  • Worker bindings declared in wrangler.jsonc; CI runs the tests inside the real Workers runtime.

Impact: proof of deploying & operating AI on cloud infrastructure, live and public.

CAOS CITY

Side project

A Roblox survival game on 12 floating islands. Each island goes into catastrophe on its own clock, and falling into the void kills you. It started as a cozy prototype called Hearthwood.

How it's built
  • 48 server services and 19 client controllers in Luau, synced from the repo into Roblox Studio with Rojo.
  • The world is built by code when the server starts (islands, towns, rivers, caves), so the place file isn't the source of truth. If one service fails, the rest keep going.
  • Player progress is saved in DataStore with session locking, retries and versioned migration; a remote guard rate-limits calls and flags exploiters.
