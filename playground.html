Data playground · local-first

SQL in your browser

Query a real snapshot of my public GitHub activity with DuckDB-WASM — the same engine behind my DataForge dashboards. The SQL runs on your device: no server, no database, nothing sent anywhere.

Try a query

Ctrl + Enter

The first run downloads the DuckDB-WASM engine (about 7 MB compressed) from jsDelivr. Every file is checked against a pinned SHA-384 hash before it runs.

Query results

Tables

repos

One row per public repository.

name, description, language, topics, license, stars, forks, size_kb, created_at, pushed_at

languages

Bytes of code per language, as GitHub detects them.

repo, language, bytes

commits_daily

Commits per day on each default branch (UTC).

repo, day, commits

pull_requests

Every pull request, open or closed (UTC).

repo, number, title, author, created_at, closed_at, merged_at

snapshot

When the data was taken, and from where.

taken_at, source

How it works

  1. The data is five small Apache Arrow files (columnar, typed) served as static files by GitHub Pages.
  2. Nothing heavy loads with the page. Your first query fetches DuckDB-WASM 1.32.0 from jsDelivr, verifies it and starts it in a Web Worker.
  3. Queries run locally, in memory. There is no backend to host, secure or pay for — the same local-first pattern I use in production.

Source: GitHub REST API, public repositories only. The exact snapshot time is in the snapshot table; the data is rebuilt with scripts/playground/build_data.py.
